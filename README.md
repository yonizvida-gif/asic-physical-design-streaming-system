# ASIC Physical Design - RTL to GDSII

A complete ASIC Physical Design implementation of a dual-clock
SystemVerilog design, taken from RTL through final GDSII using
**OpenLane 2 / OpenROAD** and the **SKY130** open-source PDK.

The project covers synthesis, timing constraints, floorplanning, power
distribution, placement, clock tree synthesis, timing repair, global and
detailed routing, parasitic extraction, multi-corner static timing
analysis, physical verification, and final GDSII generation.

## Design Overview

The design is a dual-clock streaming system containing:

-   4-tap FIR filter
-   Asynchronous FIFO for clock-domain crossing
-   UART transmitter
-   Hardware clock gating
-   100 MHz fast clock domain
-   10 MHz slow clock domain

Main data path:

``` text
data_in / valid_in
        |
        v
   Wake-Up Logic
        |
        v
     4-Tap FIR
        |
        v
  Asynchronous FIFO
        |
        v
    UART Transmitter
        |
        v
     tx_serial
```

The FIR operates in the fast clock domain. Filtered samples cross into
the slow clock domain through a Gray-coded asynchronous FIFO with
two-flip-flop pointer synchronizers.

The design contains two intentionally asynchronous clock domains, making
CDC handling and timing constraints an important part of the
implementation.

## ASIC Clock Gating

The ASIC implementation uses the SKY130 integrated clock-gating cell:

``` text
sky130_fd_sc_hd__dlclkp_1
```

The integrated clock gate provides a technology-appropriate glitch-free
implementation and allows the gated FIR clock to participate correctly
in clock tree synthesis and static timing analysis.

The final design contains one integrated clock-gating cell.

## Timing Constraints

Two primary clocks are defined:

``` tcl
create_clock -name clk_fast -period 10.000 [get_ports {clk_fast}]
create_clock -name clk_slow -period 100.000 [get_ports {clk_slow}]
```

The two clock domains are declared asynchronous:

``` tcl
set_clock_groups -asynchronous \
    -group [get_clocks {clk_fast}] \
    -group [get_clocks {clk_slow}]
```

Interface assumptions used for the Physical Design implementation:

``` text
Input delay minimum = 0.5 ns
Input delay maximum = 2.0 ns
Clock uncertainty   = 0.2 ns
```

These are portfolio implementation assumptions rather than measured
external-interface specifications.

`rst_n` is an asynchronous reset and is intentionally not modeled as
ordinary synchronous input data.

`tx_serial` is a protocol-driven UART output and is intentionally
excluded from synchronous output timing analysis.

The broad reset false-path approach was intentionally avoided so that
reset-related timing behavior is not silently hidden.

CTS builds physical clock distribution networks for:

-   `clk_fast`
-   `clk_slow`
-   Gated FIR clock

Clock buffers and inverters were inserted to control clock transition,
fanout, latency, and skew.

## Parasitic Extraction and Post-Route STA

After detailed routing, interconnect resistance and capacitance were
extracted and included in timing analysis.

Post-route timing was evaluated across nine PVT/RC analysis
combinations.

Final worst-case timing:

``` text
Worst Setup Slack = +2.434 ns
Worst Hold Slack  = +0.088 ns

Setup TNS         = 0 ns
Hold TNS          = 0 ns

Setup Violations  = 0
Hold Violations   = 0

Max Slew Violations        = 0
Max Capacitance Violations = 0
```

Worst setup slack occurred in the slow timing corner, while worst hold
slack occurred in the fast timing corner.
